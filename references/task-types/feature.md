# feature（新功能）

适用条件：本次变更要交付此前不存在的能力或对外契约——新接口、新数据结构、新流程。恢复既有契约走 bugfix.md；不改行为的结构调整走 refactor.md。

## 契约先定

- 实现开始前冻结三样东西：接口签名与调用方式、数据结构及其不变量、错误语义（什么算失败、如何报告、调用方如何恢复）。冻结后的契约同时是实现边界和验收判据。
- 契约落在任务书或设计基准里。实现中发现契约不成立——签名表达不了需求、错误语义覆盖不了真实失败——停下来报回派发方修订契约，不在代码里静默扩展。

## 增量编写

- 按垂直切片推进：每片贯通涉及的各层，自带能验证该片行为的测试或检查；不先写完所有底层再一次性拼装。依据：workflow-repos-comparison.md §C.1 共识 2（垂直切片为任务最小单位）。
- 每片闭环后再开下一片：本片的检查转绿、状态可交代，才扩大改动面。
- 切片大小以单个上下文可闭环为准；需要靠记忆衔接前后两半的，先拆小。
- 切片划分按用户可验证的行为切，不按技术层次切；「先把数据层全部做完」是横向切片，中间任何一步都没有可验收的行为。

## 不预埋扩展点

- 只实现被要求的能力。未被要求的抽象层、配置项、「以后可能用上」的钩子与参数不写——它们扩大审查面，并在契约外制造了无人负责的行为。
- 确有扩展性需要时，让它进契约：由任务书或设计批准明确提出，不经实现现场顺手留出。

## 用户可见面

- 新功能通常带有用户可见面：按 SKILL.md 第 5 节，实现前由 designer 给出基准，实现后由 experience-checker 独立检查。
- 错误提示、空态、加载与恢复反馈属于契约的一部分，在契约冻结阶段一并确定，不留到实现现场临时编。

## 与其它轴的关系

- 角色轴：实现纪律与候选交接见 `references/worker.md`；用户可见基准见 `references/designer.md`；独立体验检查见 `references/experience-checker.md`；验收运行见 `references/verifier.md`。
- 项目适配层：验证入口、命令适用条件与证据位置见 `references/project-adapter.md`。
